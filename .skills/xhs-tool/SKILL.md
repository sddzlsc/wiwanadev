# 检查、修改并打包小红书小工具

请将当前工作区应用打包为**小红书小工具**。

## 工作流程

1. 读取当前src/ 路径下的项目代码，如果代码未实现，需要等项目代码实现后再执行后面的链路，禁止干扰代码生成
2. 如果项目代码已经生成，读取src/下的项目代码，了解当前的项目结构，并根据重点检查中的要求，进行分析  
#### 重点检查：
  - 项目结构、代码、配置和资源
  - 是否存在不支持的能力，包括数据库、网络 API 等
  - 构建及打包要求
  - 移动端适配和使用体验

1. 读取 [guide.md](references/guide.md) 在task/目录下新建一个 xhs-项目名(英文名)的工作目录，生成打包需要的文件，***禁止直接在原始的项目代码中进行修改，必须以最终通过小红书小工具校验为目标， 生成文件时需要考虑移动端适配问题，不单独输出适配结果。
2. 读取 [guide.md](references/guide.md) 对task/目录下新建的工作目录进行打包，打包为一个zip
3. 根据 [guide.md](references/guide.md) 中关于zip 的限制进行校验，同时对zip 大小进行限制，不允许超过10M，当zip中出现图片导致超出zip 包大小时，需要对图片进行裁剪，请注意也是只对task/ 目录下的内容进行修改，最多尝试1次，如果无法压缩到10M以下，告诉用户进行修改

Remind zip文件中仅允许以下文件类型：jpg、css、gif、svg、png、js、jpeg、json、html、woff2、webp、woff。

## 输出

**📦 代码包**

> **改造点**：xxx
> **校验结果**：通过
> **产物路径**：`/workspace/app-id/tasks/xxx.zip`
> `files  /workspace/app-id/tasks/xxx.zip` 

**只有最终校验通过并成功生成 ZIP 包后，才能输出产物路径。包含代码块的files也是必须要输出的**
