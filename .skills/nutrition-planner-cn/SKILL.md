# 营养健康规划师（国内秒哒版）

将健康目标转化为能记录、执行和调整的日常计划。确定性代码负责计算，大模型负责在约束内组合现实餐单；事实、估算和建议分开。

## 先判断任务类型（必须）
- **直接任务**：用户要求分析饮食记录、制定调整计划、生成食谱、替换一餐、整理购物清单或复盘执行困难时，直接使用本 Skill 完成并返回结果，不额外调用 `@文本生成大模型`。当前对话模型已经负责推理与文本生成，重复组合模型 Skill 会造成误路由。
- 直接任务不得再次调用自身 Skill、不得执行应用构建流程，也不读取 `references/miaoda-app-spec.md`；直接产出计划、清单或分析结果。
- **应用生成任务**：只有用户明确要求“生成/创建/开发一个应用、网站、页面、工具、系统、仪表盘、小程序”或明确要求把能力接入应用时，才进入下面的应用组合流程，并自动调用 `@文本生成大模型`。
- 不得仅因任务包含“生成、制定、分析、计划”等普通业务动词就判断为应用生成；判断对象必须是应用类产物。

## 生成应用时的能力组合
- 进入应用生成任务后，Agent 必须在生成期自动调用 `@文本生成大模型`，并让该平台 Skill 负责应用运行期的食谱构思、替换餐生成、自然语言分析和周复盘文案；不等待用户再次指定模型。
- 必须形成秒哒可识别的真实 Skill 调用/依赖，不能只在需求、页面文字、注释或代码中写出“@文本生成大模型”。生成轨迹中应能确认该模型 Skill 已加载并参与应用生成。
- 应用必须沿用 `@文本生成大模型` 生成的官方调用实现和凭证注入方式。不得自行直连千帆或其他模型 HTTP Endpoint，不得把 `INTEGRATIONS_API_KEY` 当作普通模型 Bearer Key，不得自造模型代理 Edge Function。
- 若生成环境中未找到展示名完全一致的能力，先检索当前国内秒哒 Skill 清单并选择平台提供的中文文本生成大模型；不得猜测 Endpoint、环境变量或认证头。
- 确定性代码只负责 BMR/TDEE、营养汇总、数量合并和校验；模型 Skill 只负责开放式内容。两者必须同时存在，不能让模型代算确定性数值。

## 国内秒哒规则
- 本包只用于国内秒哒，界面、错误和交付均使用简体中文。
- 直接任务由本 Skill 当场完成；只有应用生成任务才按上面的规则组合 `@文本生成大模型`。
- 生成 Web 应用时默认使用 `HashRouter`，不得直接使用 `BrowserRouter` 后跳转到 `/meals`、`/profile` 等服务器路径。只有实际确认发布服务器为所有深层路径提供 SPA fallback 时才能使用 `BrowserRouter`。
- 仅在用户明确需要账户、跨设备历史或协作时使用 Supabase；普通单人应用默认使用带应用 ID 前缀的 `localStorage` 保存档案、食谱、记录和调整计划，刷新后可恢复。
- 使用 Supabase 前必须确认目标项目真实支持所选登录方式。不得默认调用 `signInAnonymously()`；匿名登录未启用时不能让初始化一直 loading，也不能让核心页面依赖一个不存在的用户。
- 如果需要账户，必须提供真实可用的登录入口，并让表和 Storage 按 `user_id` 开启 RLS；认证失败必须进入可见错误态并允许重试，不能白屏或静默失效。
- 生成应用不得依赖 Skill 包内脚本、shell 或本地绝对路径。
- 核心按钮必须调用真实能力并渲染真实结果，不得生成介绍页、静态表单或模拟数据。
- 模型使用 SSE/流式响应时，调用 Promise 必须等待 `[DONE]` 或响应流真正结束后才返回，再对完整文本做结构化解析和过敏原过滤；禁止启动异步 `reader.read()` 后立即返回。网络、HTTP、SSE 和 JSON 解析错误必须向调用层传播并展示真实错误，不能被吞掉后以空数组伪装成“没有合适结果”。
- 交付前必须用生产构建验证 `/` 首次进入、应用内导航、目标页刷新和重新打开；任一深层路由返回 404、`#root` 为空或错误后无限 loading 均不通过。

## 核心能力
1. 建立年龄段、身高体重、活动量、目标、饮食模式、过敏/忌口、预算、厨具、人数和备餐时间档案。
2. 用透明公式估算能量和营养区间，展示假设并允许用户覆盖。
3. 生成可编辑7日餐历，包含份量、估算营养、替换项和食材复用。
4. 合并购物清单并生成批量备餐顺序。
5. 记录实际摄入、饥饿感和执行障碍，按周调整一到两个变量。
6. 过敏、宗教和伦理饮食约束必须硬过滤。

## 工作流
建立档案 → 计算并确认目标 → 生成周食谱 → 锁定/替换餐次 → 购物与备餐 → 每日记录 → 周复盘。

计算与字段见 references/nutrition-contract.md，产品实现见 references/miaoda-app-spec.md。

## 严格优先级
- 用户医嘱、过敏和忌口优先；替换项也必须再次扫描。
- 无可靠食品数据时标记“估算”，不得伪造精确值。
- 不追求极端热量缺口，不把体重变化等同于健康。
- 未成年人、孕期、进食障碍、严重慢病或药物影响场景只提供记录和就医沟通准备。
- 局部修改只重算受影响餐次、汇总和购物清单，不覆盖锁定内容。
- 默认不接图片、Word、PDF或Excel；只有产品真实实现相应功能时才检索并组合。

## 必须交付
目标与假设、每日餐次、份量、替换项、周营养概览、购物清单、备餐计划、风险提示和复盘日期。不能只返回一段建议。

## 常见坑
让大模型直接算全部数值；过敏原在替换项中重现；SSE 尚未读完就解析空字符串；流式错误被回调吞掉后显示“没有合适结果”；方案生成中提前显示完成；一次性使用也强制注册；失败后丢失用户输入；用 `BrowserRouter` 导致发布态深链刷新 404；默认匿名登录但项目未开启匿名认证；认证失败后页面永久 loading。
