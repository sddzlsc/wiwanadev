# 外部集成 Debug 准则

适用症状：第三方接口报错/返回异常、上传失败、配额耗尽、平台限制导致功能不可用、文件解析报错。

---

## 第三方 API 接入

### 接入未知 API 前先 curl 探真实端点

对接未知外部 API 时，不要凭常见范式或臆测写鉴权代码。先对真实端点做最小探测：

- curl 打通一次最简请求
- 仔细读鉴权失败响应（缺什么头/参数、报错文案怎么说）
- 严格按响应要求补齐头和参数
- 注意区分"账号名"与"内部数字 ID"等易混参数

让端点的真实响应告诉你要什么，而不是猜。凭据/属主 ID 等用户私有信息向用户索取。

### 后端/第三方接口失败时先查真实返回

遇到"还是显示原始值/空值/数字"的重复反馈时，立刻查对应 Edge Function 或第三方接口的真实返回码和返回体。只有确认后端确实返回了正确数据，才认为是前端展示问题；否则先修后端、配额、密钥或网关配置。

---

## 平台约束

### 选架构前先验证平台关键约束

选择涉及平台托管服务的技术架构前，先确认关键约束：

- Edge Function / Lambda 的内存上限、执行超时
- 请求 body 大小限制
- 平台代理/网关的路径重写和拦截规则

如果方案的资源需求超出约束（如需要在 150MB 内存中持有 500MB 文件），立即换方案而不是在细节上修补。

### 平台代理可能拦截特定请求

TUS、WebSocket、大文件 PUT 等非标准请求可能被平台代理拦截或重写。如果上传/连接卡住，先验证请求是否真的到达了目标服务，而非被中间层截断。

---

## 文件上传

### multipart/FormData 调用必须确认请求到达

涉及 multipart/form-data 的 Edge Function 调用：

- 优先使用原生 fetch 而非 SDK 封装
- 改动后通过网络面板确认请求已发出并收到响应
- 不能只看控制台无报错或 SDK 无异常就认为成功

---

## 文件解析

### 依赖库的运行时兼容性

在 Deno Edge / 浏览器 等受限环境中使用文件解析库时：

- 确认库是否依赖 Node.js 专有 API（fs、path、Buffer）
- 确认库的版本是否使用了运行时不支持的新 API
- 优先选择明确标注 browser/edge 兼容的包或版本

---

## 排查顺序（定位根因用）

1. curl/fetch 直接请求目标端点，观察真实返回码和 body
2. 检查网络面板确认请求是否发出、是否被中间层拦截
3. 确认凭据/配额/密钥是否有效（过期、格式错误、配额耗尽）
4. 确认平台约束（内存、超时、body 大小）是否被突破
5. 最后才查业务逻辑和前端展示
