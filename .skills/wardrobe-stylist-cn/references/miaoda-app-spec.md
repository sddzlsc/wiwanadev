# 国内秒哒应用规格
页面：风格档案、衣橱网格、今日穿搭、周日历、胶囊衣橱、旅行打包、缺口购物、导出与删除。
图片流程显示 uploading、analyzing、review、ready、failed；确认后才入库。效果图必须完整轮询到真实预览和下载。
默认数据层使用 `${VITE_APP_ID}:wardrobe:` 前缀的 `localStorage`，保存单品、洗护状态、穿搭、周计划、胶囊衣橱与旅行清单。只有明确需要账户或跨设备时才接 Supabase。
验收：
1. 只有5件衣物时，所有造型仅引用这5件。
2. 待洗单品不进入次日方案。
3. 删除单品后相关穿搭标记待修复。
4. 打包清单每件衣物对应具体日期或备用用途。
5. 未开启匿名登录时，免登录版本仍可建档、保存、生成并刷新恢复；账户版必须通过真实登录后才访问 RLS 数据。

## 认证与数据层（强制）
- 禁止在通用 API/CRUD 初始化函数中自动调用 `signInAnonymously()`。匿名认证只有在产品明确选择该模式、目标环境已实测启用且 UI 对该会话模式有清晰处理时才可使用。
- AuthProvider、登录 UI、Session 恢复、UUID owner 字段和 RLS 必须同时成立。不得注释认证组件后保留 `owner_id uuid default auth.uid()` 与 `to authenticated` 策略，也不得用隐藏匿名登录弥补缺失的认证入口。
- `Anonymous sign-ins are disabled`、4xx/422 或无 Session 时立即结束 loading，展示认证不可用与重试路径，并阻止依赖用户身份的表和 Storage 请求。不得把该错误伪装为空衣橱。
- 没有账户需求时删除认证依赖，改用 App ID 命名空间本地存储；图片如必须上传，应采用平台支持且与产品身份设计一致的存储流程，不能为上传图片反向强制整个应用匿名登录。

## 流式模型调用与穿搭解析（强制）
1. SSE 消费函数只能在 `[DONE]`、`reader.done` 或明确失败后结束 Promise；使用可等待的读取循环或完成 Promise，禁止启动递归读取后立即返回。
2. 今日穿搭、周计划、胶囊衣橱和旅行清单必须先拼接完整文本，再执行 JSON/Schema、真实库存、洗护状态和场景约束校验；流结束前不得判空或结束 loading。
3. 分别处理 HTTP/网关失败、SSE 中断、JSON/Schema 失败和约束过滤后为空。前三类展示真实错误，只有最后一类可提示“现有可用单品无法组成符合条件的穿搭”。
4. 回调内部 `throw` 不能代替外层 Promise reject；底层错误必须传到页面 `catch`。验收覆盖跨 chunk JSON、4xx/5xx、中途断流、无效 JSON 和所有候选引用不可用单品，并保留衣橱与用户条件。
