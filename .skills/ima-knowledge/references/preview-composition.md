# 预览能力组合与验收 r5

## 先确定用户可见结果
本次模式为 preview-only：保留知识库、列表、搜索、下载，正文提取页面与 AI 问答不默认生成。原文件页面应包含完整图文关系。内部 ZIP/XML/布局解析属于渲染实现，不是用户要求删除的“提取正文”。

## 生成前能力盘点
逐格式检索目标 QA 实际可用 Skill、内置组件与服务，读取真实说明与接口，记录名称、版本、运行位置、是否支持现有文件输入、输出是否完整页面、配置与费用。组合要有生成轨迹证据，普通文字 @ 不算调用。未经确认不编造技能名。

本地云端包快照初查（不证明 QA 当前可用）：
- excel-handler：说明 Web/Mobile/通用任务按技术栈实现导入解析导出，不足以证明完整工作簿保真预览已提供。
- ai-ppt-generator：根据主题生成 PPT，不是对上传的原 PPT 做页面预览；不能作为本任务的转换器。
需要继续检索真实渲染/转换能力，不因名字含 Excel/PPT 就认定满足需求。

## 格式责任与实现顺序
- PDF：前端 PDF.js；打开即下载原文件，使用本地匹配 worker。无需后端 PDF 提取成功。
- PNG/JPEG：Blob + img，独立加载与资源释放；不依赖 OCR 或 Office。
- DOCX：验证文档渲染组件或转换服务，图文、表格、分页及字体对照原文件；HTML 重排不能标为完全原版。
- XLSX：验证工作簿渲染，保留工作表、单元格位置、样式及合并关系；打印 PDF 与交互工作簿不是同一体验，按用户要求选择。
- PPTX：验证幻灯片渲染或转页面能力；禁止素材图片拼盘替代整页。
- TXT/Markdown：直接文本/格式化显示，HTML 清洗；笔记走笔记接口；网页链接与正文区分。

## 复用资产与诚实范围
scripts/baseline/PdfView.tsx 为旧应用已展示成功的组件快照，不含凭证。配套接口、UI 依赖与类型见同目录 INTEGRATION.md；不能只复制组件而漏掉依赖。二进制转换使用 scripts/preview-bytes.mjs。reader-route.mjs 默认 preview-only，不触发 extraction。
DOCX/PPTX已提供浏览器兼容渲染资产，参见 office-runtime.md；不需要转换服务，发布态仍须验收，不能将占位路由当作完整能力。缺依赖时列为未完成，不宣称包能让所有格式显示。已有内容展示如需保留，只能明确标为兼容阅读；不擅自恢复用户已取消的提取界面。

## 单独验收，禁止回退
为每种格式记录获取成功、显示真实内容、版式覆盖范围、切换/取消、下载、运行环境。确保 PDF/图片即使解析服务故障仍能打开；只预览时 Network 不出现 read_file/ask 请求。截图、页数、工作表数对照原文件。静态检查不代替运行验收。
先确认 QA 实际加载版本与 SKILL.md 的当前版本一致，再用相同 query 和文件复测。若原 query 明确要求提取/问答，与后续 preview-only 意图冲突，先向用户说明并确认测试目标，不能悄悄改 query，也不能默认生成用户已取消的功能。
