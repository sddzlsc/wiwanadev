# 原版页面预览：实现与验收

## 目标与边界
- 阅读区默认呈现原文件页面，保留图文位置、页序和版式。提取正文用于检索和引用；仅在用户需要时提供辅助正文视图。
- ima 文件获取、正文提取、页面渲染、AI 问答分别验收。原文件下载成功不等于预览成功；关键词片段检索不等于 AI 问答。
- PNG/JPEG 展示原图不依赖 OCR。扫描 PDF 展示页面也不依赖 OCR；仅文字识别才需要另行验证的 OCR 能力。

## PDF 已定位的实现陷阱
- 服务端按二进制返回文件，保留正确 Content-Type；JSON 错误响应不得送入 PDF.js。
- TypeScript 的 `as ArrayBuffer` 或 invoke<ArrayBuffer> 不转换运行时对象。优先从经过鉴权且状态已检查的 Response.arrayBuffer() 取得原始字节；若 SDK 返回 Blob，必须调用 arrayBuffer()。若 SDK 已把二进制解码成字符串，不用 TextEncoder 修复，改用原始响应重新读取。
- 参考转换函数见 [二进制示例](../scripts/preview-bytes.mjs)。服务调用、鉴权及错误状态检查由应用按已验证接口实现，示例不包含密钥或新增网关。
- PDF.js 获取数据时使用独立副本：`getDocument({data: new Uint8Array(buffer.slice(0))})`，避免 worker 转移后复用共享缓冲区。切换文件取消渲染与加载任务，清理文档和 Blob URL，阻止旧请求覆盖新文件。
- worker 与库版本严格一致并随部署发布。按需渲染页面，支持翻页、页数、缩放及适应宽度；缩放后的页面边缘应可通过滚动访问。

## Office兼容预览（用户确认 r16）
用户已接受兼容预览，不承诺原生分页一致。复用 [office-runtime.md](office-runtime.md) 的浏览器实现，DOCX/PPTX不需要额外服务。保留图文关系和原文件下载，不拆成素材列表或正文提取界面。其他格式单独验证；系统技能名称不证明运行期支持。严格原生保真需求不以兼容预览冒充完成。

## 发布前验收
- PDF：普通图文、多页、扫描页；原文对照图文/页数；反复切换、重新挂载、翻页、缩放；零字节、JSON 错误和取消请求分别验证。
- PPT：页数、页序、文字与插图位置对照原文件；不以素材数量代替页数。
- Word/Excel：使用真实图文/多表文件，检查字体及分页，不只使用纯文本最小样本。
- 问答只使用当前文件有证据的正文，引用实际页码；无正文时明确状态。
- 报告分别标明静态检查、本地测试、云端实测和未验证项。新应用复用原始 query、相同文件，不以定制 query 掩盖 Skill 问题。
