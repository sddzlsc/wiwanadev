# 运行时与文件分流基线 r3

## 回退来源与复用范围
旧 app-e6kea3chicch 使用 fflate@0.8.3、fast-xml-parser@4.5.0，具有独立图片与 PDF 处理；新 app-e8vg0rq8vls1 却在 Edge 使用裸 DOMParser、以两条猜测域名限制下载、将图片送入 Office 分支。不要把旧应用所有代码整体复制：仅复用确认的模块，不复制凭证、项目 ID、文件 ID 或未验收功能。

## 服务端 XML
复用 scripts/server-xml.ts 的运行时显式依赖示例。浏览器 DOMParser 不作为 Edge 默认全局变量；禁止在服务端直接 new DOMParser()。普通 XML 对象树与 preserveOrder 树结构不同，调用方必须与解析器选项匹配。保留 p: 等命名空间前缀，访问实际根节点；关系文件 Target 做路径归一化，不允许目录穿越。部署后用包含中文、字符引用、属性和多页关系的 Office 文件冷启动实测。示例新增封装本身尚未经过 QA 部署，不把原应用成功等同于示例全量验收。

## 下载：以 mediaId 为入口，不以任意 URL 为入口
- 前端提交 mediaId；服务端验证应用用户对当前知识库/文件的权限，再调用 ima get_media_info 获取本次下载地址和必要头。不要接收前端任意 url、headers 直接代理。
- 域名策略必须依据实际响应及可信服务文档确认，并配置精确允许的存储端点；不要猜测“只能 ima.qq.com / myqcloud.com”，也不要以取消校验修复失败。
- 仅 HTTPS，拒绝 userinfo、内网/环回/链路本地目标；使用部署环境可实现的 DNS/出口策略防止 SSRF。重定向逐跳检查目标，跨域不得继承敏感头；限制跳数、时长和字节数。能力不足时报告配置要求。
- 下载域名拒绝属于下载策略错误，不标为解析失败或文件损坏。日志只含脱敏 host、阶段、状态码及字节数，不输出签名查询串/凭证。
- 返回二进制时保留实际 MIME；前端复用 preview-bytes.mjs。错误 JSON 不传给预览器。原文件获取与正文解析分开，后者失败不能阻止原图/PDF预览。

## 分流必须有实现，不仅有文案
使用 scripts/reader-route.mjs 在解析前分流。
- media_type=9：下载图片 Blob，createObjectURL 后以 img 展示，切换时 revokeObjectURL；不调用 parse_office，不要求 OCR。
- media_type=1：交给 PDF.js 真实页面渲染，正文提取独立执行。
- 3/4/5：正文走对应 Office 解析器；页面预览走经过验证的服务，缺服务时诚实标为待配置。
- 2：链接与正文区分；7/13：文本；11：笔记接口，不把笔记送进 ZIP。
- 示例路由返回值仅为模块契约，生成应用必须真正连接处理器，不能返回未消费的字符串就宣布完成。

## 回归门槛
同一批 PDF、PNG、DOCX、PPTX、XLSX 分别测试获取、预览和正文，不允许重新生成后已通过的 PNG/PDF 消失。图片的 extraction=null 为正常状态。模拟域名拒绝、过期地址与非2xx，并确认提示属于正确阶段。先确认 QA r3 包加载，再生成；若未确认，只能记录版本未确认，不作为新包有效性结论。
