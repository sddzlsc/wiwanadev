# Word、PPT、网页预览补充（2026-09-11）

适用：修复阅读应用中未通过的 DOCX、PPTX、网页分支。保留现有 PDF、PNG/JPEG、TXT/Markdown 的下载、校验、组件和测试，不以全局重写实现本补充。Excel 未在本次修改中新增实现。

## 系统技能参考：按内容选择，不按名字猜能力
已检查本地 baidu/system 快照（不是 QA 当前运行能力证明）：
- `docx/SKILL.md` 的 Converting Documents to Images 明确给出 `soffice --headless --convert-to pdf document.docx`，再用 `pdftoppm` 转整页图片。读取该节借鉴原文档转换；不要走 Pandoc 文本提取或 docx-js 重建文档来冒充原版。
- `pdf/scripts/convert_pdf_to_images.py` 使用 pdf2image/Poppler 转整页 PNG，默认最长边1000像素。它不是 Office 转换器；若使用先创建输出目录。已有 PDF.js 能展示时直接用转换后的 PDF，不必再转图片造成清晰度损失。
- `ppt-generator` 的 PptxGenJS、XML 解包/打包和结构检查用于制作编辑，不是现有 PPTX 页面渲染器。不通过重新生成 PPT 或读取 ppt/media 来预览原文件。
- `data-analysis` 是数据分析，不引入当前预览流程。
生成环境若可访问这些系统技能，读取上述相关章节；没有访问能力时不要伪造调用记录。本参考自带实现方向，不依赖用户机器的绝对路径。系统技能可在生成阶段执行工具，不代表发布应用拥有这些工具。

## Word / PPT：浏览器兼容预览

按 [office-runtime.md](office-runtime.md) 使用包内浏览器实现，不要求转换服务器。用户已接受兼容分页，保留完整图文而非提取素材或重写内容；PDF/PNG/TXT不动。生成期系统技能中的LibreOffice命令仅用于参考，不是本次运行依赖。

## 网页：先真正尝试展示，不写死失败

已有完整HTML时优先走已验证的 `scripts/web-preview.mjs` + DOMPurify 3.4.15 隔离静态预览，具体接线与范围见 [web-preview-runtime.md](web-preview-runtime.md)。不为了等待原站URL丢弃已获取的HTML。下列原站嵌入能力仍按实际站点验证。
1. 区分网页条目的原站 URL 与下载返回的 HTML；从实际元数据字段取值，不猜 ima 字段。保留用户可点击的原网页入口，不标成“下载文件”。仅有入口不算内嵌预览通过。
2. 有原站 URL 时校验 http/https 协议，实际接入隔离 iframe。按业务最小化 sandbox 权限；默认不向外站传应用凭据、不允许顶层跳转。跨域页面的 iframe onLoad 不证明内容已成功显示，也不要凭 onError/超时就断言是 CSP/X-Frame-Options 限制。通过浏览器实测确认。
3. 若内嵌受限且应用具备已批准的静态快照能力，后端获取 HTML，在隔离来源展示净化后的快照。使用可靠 HTML 清洗器移除脚本、事件属性、表单和危险协议；禁止把未清洗 HTML 注入应用主 DOM。资源 URL 按原网页地址解析，相对图片/CSS需处理；服务端每次重定向、资源抓取均校验目的地址，避免任意内网请求，并设体积/超时上限。
4. 静态快照不是完整交互网站；标注“静态预览”，不承诺登录、脚本和动态资源工作。未实现快照时保留原站入口并明确未完成内嵌验收，别写“内容已获取”却不展示任何内容。

## 本补充验收
- 已支持分支：修改前后校验现有脚本哈希；运行 test-preview.mjs 保证原有离线用例通过。
- Office：真实原文件→浏览器兼容预览组件，核对全部页数/页序、图文；再测中文字体、渲染失败、切换文件和原文件下载。
- 网页：允许内嵌、禁止内嵌、相对图片/样式、动态页面各测；分别标记原站嵌入/静态快照/只提供原站入口，禁止混报。
- 本补充包含浏览器实现，不包含额外转换服务。静态检查、本地转换、QA运行与线上验收分别报告。
